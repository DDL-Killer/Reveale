## 什么是地址?

* 地址只是数字,描述各种符号在源程序中的位置,它是源代码文件中各个符号偏移开头
* 编译器的工作就是给各个符号编址,编译器根据所在硬件平台的特性,将源码中的符号(指令和数据)按照平台的特性分配空间
* 程序中各种数据结构的访问,通过"该数据结构的起始地址+该数据结构所占的内存大小"实现----这就是为什么定义变量要给出变量类型,因为变量类型规定了变量所占的内存大小
* 占据在第一位的数据,便是整个程序的起始地址
* 数据的地址,其实就是该数据相对整个程序开头的距离,即偏移量
* 偏移量的本质就是地址,每个变量的地址是前一个变量的地址+前一个变量的内存空间大小
* 编译器给程序中各符号分配的地址,就是各符号相对于文件开头的偏移量

## 什么是section?

* 编译器提供的关键字只是为了让程序员在逻辑上将程序划分为几个区域,是伪指令
* 关键字section并没有对程序中的地址产生任何影响,即在默认情况下,也没有section都一样,section中数据的地址仍然是相对于整个文件的顺延,仅仅是在逻辑上让开发人员梳理程序之用

## 什么是vstart

* vstart是虚拟起始地址
* 是为section内的数据指定一个虚拟的起始地址
* 编译器以相对于文件开头偏移来编址的好处是利于重定位,整个文件加载到某个地址后,可以以这个地址为段基址
* 程序只有加载到非0地址时vstart才是有用的,程序默认起始地址是0
* vstart只是告诉编译器以新的数字作为后面数据的地址的起始值,它本身没办法改变数据本身在文件中的地址

## CPU的实模式

### CPU的工作原理

大体上分为三个部分,控制单元,运算单元,存储单元

* 控制单元是CPU的控制中心,由指令寄存器IR,指令译码器ID,操作控制器OC组成,程序加载到内存后,指令指针寄存器IP指向内存下一条待执行指令的地址,控制单元根据IP寄存器的指向,将位于内存中的指令逐个装载到指令寄存器中,指令译码器将位于指令寄存器中的指令按照指令格式来解码

  指令格式

  | 前缀 | 操作码 | 寻址方式 操作数类型 | 立即数 | 偏移量 |
  | ---- | ------ | ------------------- | ------ | ------ |
  |      |        |                     |        |        |

* 存储单元是指CPU内部的L1 L2缓存及寄存器,待处理的数据就存放在这些存储单元里面
  * 缓存采用的都是SRAM(static RAM),主板上属于DRAM(Dynamic Random Access Memory)
  * 寄存器分为两大类
    * 可见寄存器
    * 不可见寄存器
* 过程
  * 用户进程的代码段映射到内存,内存上有很多指令,CPU的控制单元中的操作控制器OC从内存中取得命令后,由指令指针寄存器IP得到待运行的指令地址
  * 交给指令寄存器,指令寄存器得到指令开始解码后发给运算单元
  * 存储单元从内存中获得操作数
* 总结:控制单元取下一条待运行的指令,该指令在程序计数器PC中,cs:ip,读取ip后,将地址送上地址总线,CPU得到了指令,确定操作码,再确定操作数类型,如果在内存中,将操作数取回放到自己的存储单元,操作控制器给运算单元下令执行,ip寄存器继续加上当前指令大小恢复先前操作继续循环

### 实模式下的寄存器

* 寄存器是一种物理存储元件,比一般的存储介质要快
* 缓存解决了速度不匹配设备之间的数据传输
* 浏览器在请求一个域名IP时
  * 浏览器内部有dns客户端,查询本地dns缓存中是否有该域名的ip,有就直接访问,没有再去查找自己主机所设置的dns服务器,然后去该dns服务器查询
  * 如果dns服务器本地缓存有该域名的A记录,直接返回浏览器dns,没有就递归向上查询
  * 浏览器的dns客户端在得到ip后,将该域名和ip放到自己的缓存
  * 浏览器开始通过网络用http协议访问该ip地址的80端口
  * ip地址对应的设备不是最终的Web服务器,一般是网关,由网关检查本地缓存中是否有相关Web服务器的缓存,如果有就请求分配给缓存中的Web服务器,随后将web服务器和ip地址和端口号缓存
  * web服务器拿到请求,静态就检查,直接取,动态就交给自己的cgi处理
  * cgi先看自己的缓存,没有的话,与数据库建立连接,发出请求
  * 数据库先检查自己的缓存,没有的话从结果中检索返回,将结果集缓存
  * cgi拿到数据,返回Web服务器,存缓存
  * Web服务器将数据返回网关
  * 网关返回浏览器
  * 浏览器发现有静态数据,存到internet临时目录
* 如果缓存刚好有需要的内容,称其为命中hit,否则就是缺失mis
* 寄存器分两类
  * 内部使用,不可见,全局描述符表寄存器GDTR 中断描述符寄存器IDTR 局部描述符表寄存器LDTR 任务寄存器CR0~3 指令指针寄存器IP 标志寄存器flags 调试积存器DR0~7
  * 可见的寄存器,段寄存器 通用寄存器 
  * 段内偏移地址，相对于此起始地址的偏移量
  * 访问内存，通过地址总线，给地址总线一个数字
  * 访问内存就需要提供地址，初次访问，用寄存器来存储内存地址，由于要指定的是内存中的一段区域的起始地址，所以称之为段基址寄存器，也称段寄存器
  * 代码段寄存器CS就是用来指向内存中的这段指令区域的起始地址
  * 数据段寄存器DS就是用来指向此区域的起始地址
  * 段栈寄存器SS就是用来指向此区域的起始地址
  * IP寄存器是不可见的寄存器，CS寄存器是可见的寄存器，配合后便是CPU的罗盘
  * flag寄存器是计算机的窗口，展示了CPU内部各项设置、指标----实模式下的flags寄存器是16位的
* 通用寄存器，无论是实模式还是保护模式，有8个，分别是AX、BX、CX、DX、SI、DI、BP、SP
  * AX寄存器是由AH寄存器和AL寄存器组成的，都是8位

| 寄存器 | 助记           | 功能                                                         |
| ------ | -------------- | ------------------------------------------------------------ |
| ax     | 累加器         | 频度最高，算数、逻辑运算、保存与外设输入输的数据             |
| bx     | 基址寄存器     | 存储内存地址                                                 |
| cx     | 计数器         | 记录循环次数                                                 |
| dx     | 数据寄存器     | 存放数据，一般保存外设控制器的端口号地址                     |
| si     | 源变址寄存器   | 常用于字符串操作中的数据源地址，通常与其他指令配合           |
| di     | 目的变址寄存器 | 用于数据的目的地址，数据被传送到哪里                         |
| sp     | 栈指针寄存器   | 段基址是ss，用来指向栈顶                                     |
| bp     | 基址指针       | 一种用push和pop指令操作栈，另一种提供了寄存器bp，用SS：bp的方式把栈当作普通的数据段访问 |

### 实模式的由来

* 实体现在：用到的地址都是真实的物理地址

### 实模式下的内存寻址方式

1. 寄存器寻址
2. 立即数寻址
3. 内存寻址
   1. 直接寻址
   2. 基址寻址
   3. 变址寻址
   4. 基址变址寻址

* 什么是寻址？----找到“数”的所在地，从哪来，到哪去

* 寻址器寻址----数在寄存器中，直接拿
* 立即数寻址----操作数直接存在指令中，直接拿过来就能用
* 内存寻址----操作数在内存中的寻址方式称为内存寻址
* 直接寻址----直接在操作数中给出的数字作为内存地址
* 基址寻址----在操作数中用bx寄存器或寄存器作为地址的起始，地址的变化以它为基础
* 变址寻址----寄存器由bx、bp变成了si和di
  * si是指源索引寄存器
  * di是指目的索引寄存器
  * 两个寄存器的默认段寄存器都是ds
* 基址变址寻址----基址寄存器bx或bp加上一个变址寄存器si或di

### 实模式下的ret

* call、ret、jmp在原理上修改寄存器CS和IP的值，将CPU导向新的位置
* call指令调用函数时，压入返回地址
* 对于CPU来说，靠程序计数器PC来指路，在内存中创建栈，CPU在栈中保留程序计数器PC的值，保留返回地址给ret或retf准备
* ret指令的功能是在栈顶弹出2字节的内容来替换IP寄存器，所以被回收的栈顶空间使sp指针值变大，ret指令中会使sp指针+2
* retf是从栈顶取得4字节，栈顶处2字节替换IP寄存器，另外的2字节替换CS寄存器，retf指令会使sp指针+4
* call和ret是一对配合，用于近调用和近返回；call far和retf，用于远调用和远返回

### 实模式下的call

* 8086有两个指令用于改变程序流程，一个使jmp，另一个call
* jmp去执行新的代码，适用的环境是“交接”
* 在汇编中，用call命令实现一个函数的调用
* 实模式下，call指令调用有四种方式
  1. 16位实模式相对近调用----“近”就是在同一段内，不用切换段，不用换段基址，只需给出段内偏移地址；相对时在同一个代码段内，只需要给出目标函数的相对地址；指令格式是`call near 立即数地址`，指令占3字节，0xe8是操作码，剩下2字节是操作数
  2. 16位实模式间接绝对近调用，间接指相对地址，要么在寄存器，要么在内存，绝对指目标函数地址是绝对地址
  3. 16位实模式直接绝对远调用，直接给出的是立即数，远意味跨段，一般形式为`call far 段基址（立即数）：段内偏移地址（立即数）`
  4. 16位实模式间接远调用`call far 内存寻址`'

### 实模式下的jmp

* 无条件跳转，将程序流转移到新的位置
* 一共有5种转移方式
  * 16位实模式相对短转移，机器码大小2字节，操作码是`0xeb`
  * 16位实模式相对近转移`jmp near 立即数地址`，操作码是`0xe9`
  * 16位实模式间接绝对近转移`jmp near 寄存器寻址 or 内存寻址`,操作码`0xff`
  * 16位实模式直接绝对远转移，操作码`0xea`
  * 16位实模式间接绝对远转移

### 标志寄存器flags

* 有条件转移的指令标志放在标志寄存器flags中
* 实模式下的标志寄存器是16位的flags，在32位保护模式下，扩展了标志寄存器，称为32位的eflags

### 有条件转移

* 是一个指令族，如果条件满足，jxx会跳转到指定位置去执行
* 格式`jxx 目标地址`，如果条件满足则跳转目标地址，否则顺序执行
* 目标地址只能是段内偏移地址

### 小结

* 被淘汰的原因，最主要是安全隐患，在实模式下，用户程序和操作系统是同一特权的程序

## 与显示器通信

* IO接口是连接CPU与外部设备的逻辑控制部件，分为硬件和软件两个部分
  * 可编程接口芯片
  * 不可编程接口芯片
* 为了简化CPU访问外部设备的工作，进行约定
  * 设置数据缓冲，解决CPU与外设的速度不匹配----设置缓冲区解决
  * 设置信号电平转换电路
  * 设置数据格式转换
  * 设置时序电路来同步CPU和外部设备
  * 提供地址译码
* 同一时刻，CPU只能和一个IO接口通信，于是，有输入输出控制中心，也就是南桥
* 南桥用于连接低速设备，北桥用于连接高速设备
* IO接口在诞生之初，被设计为要通过寄存器的方式同CPU进行通信，其内部有专门用于数据交互的寄存器，这些寄存器位于IO接口中，为了区别于CPU内部的寄存器，IO接口的寄存器称为端口
* IO接口是链接CPU和硬件的桥梁，一端是CPU，一端是硬件
* CPU提供专门的指令来完成端口的内存映射 in和out
* in指令用于从端口中读取数据，一般形式`in al，dx；`al和ax用来存储从端口获得的数据，dx是指端口号
* out指令用于往端口中写数据，一般形式`out dx，al；`
* Intel的汇编形式是“目的操作数 = 源操作数”
* 小结in和out的指令共性
  * 以上两个指令，dx只做端口，无论是作为源操作数还是目的操作数
  * in从指令端口
